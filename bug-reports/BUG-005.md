# BUG-005 — Default Applied on uses UTC calendar day

| | |
|--|--|
| Severity | Medium |
| Priority | Medium |
| Status | Open |
| Environment | Source `app/static/app.js` (`openDialog`) |
| Area | Applications |
| Case | APP-02 |
| Labels | `timezone`, `ux` |

## Summary

New applications default **Applied on** with:

```js
new Date().toISOString().slice(0, 10)
```

That is the **UTC** date, not the user’s local calendar date. In timezones ahead of or behind UTC, late evening / early morning can pre-fill yesterday or tomorrow relative to what the user expects.

## Steps

1. Set the OS timezone to e.g. `Europe/Bucharest` (UTC+3).
2. Between local 00:00 and 02:59, open **Add application**.
3. Observe the default **Applied on** value.

## Expected

Default date = local `YYYY-MM-DD` (same as what the user means by “today”).

## Actual

Default follows UTC via `toISOString()`, which can disagree with local “today.”

## Notes

I’m in UTC+3, so this is easy to miss during the day — but late at night “today” can silently become the wrong day. In some zones you could even get tomorrow and hit BUG-002/003 without touching the date. Better to format the local date instead of slicing `toISOString()`.
