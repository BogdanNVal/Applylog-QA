# BUG-004 — Auth tabs missing aria-selected

| | |
|--|--|
| Severity | Low |
| Priority | Low |
| Status | Open |
| Environment | Source `app/static/index.html` + live demo |
| Area | Accessibility |
| Labels | `a11y` |

## Summary

Sign in / Create account use `role="tab"` inside `role="tablist"`, but selected state is only a CSS class (`is-active`). There is no `aria-selected="true|false"`.

## Steps

1. Open auth view.
2. Inspect `#tab-login` and `#tab-register`.
3. Switch tabs via `setAuthMode` (click).

## Expected

Active tab has `aria-selected="true"`; the other `false` (and ideally `aria-controls` if panels are used).

## Actual

Only `class="tab is-active"` changes. Assistive tech may not announce which tab is selected.

## Notes

I can see which tab is active with my eyes. I logged this while going through the a11y checklist — small fix, but it matters for screen readers.
