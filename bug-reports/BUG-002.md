# BUG-002 — Applied on date picker allows future dates

| | |
|--|--|
| Severity | Medium |
| Priority | Medium |
| Status | Open |
| Environment | Live demo https://applylog-or59.onrender.com/ |
| Area | Applications |
| Case | APP-07 |
| Labels | `ux`, `validation` |

## Summary

The **Applied on** field is a normal `type="date"` input with no `max` (today). Users can pick a future date; the save only fails after the API round-trip.

## Steps

1. Sign in.
2. Click **Add application**.
3. Fill company + role.
4. Set **Applied on** to tomorrow.
5. Click **Save**.

## Expected

Date control blocks future days (e.g. `max` = today), or a clear client-side message before submit.

## Actual

Future date is selectable. Submit fails with a server validation error (see BUG-003 for message quality).

## Screenshot

![Future date rejected after save](../docs/screenshots/BUG-evidence-future-date-error.png)

## Notes

The API rule is fine — you shouldn’t apply “tomorrow.” What bugged me is I could pick tomorrow in the calendar and only find out after Save. A `max` on the input would catch this earlier.
